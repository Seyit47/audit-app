# Implementation Plan: Project Foundation (Init Projects)

**Branch**: `001-init-projects` | **Date**: 2026-10-06 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-init-projects/spec.md`

**Note**: Re-planned under constitution v2.0.0 and updated 2026-10-06 to use Fastify, at the
user's request. Replaces the 2026-10-05 plan.

## Summary

Create three runnable skeleton apps in one monorepo, each using its framework's standard
structure:

- **API**: Fastify + Prisma on PostgreSQL. Exposes `/v1/health` and `/v1/version`, has one
  global error format and structured logs with request IDs, and generates API docs from code.
- **Admin web**: Next.js. The sidebar layout from the design, RU/EN, and a backend status
  indicator.
- **Mobile**: one Flutter app with a feature-first clean architecture, Agent and Admin tab
  shells chosen by role, RU/EN, light and dark themes, and an "update required" check.

One CI workflow runs lint, type checks, tests and the migration status check for all three apps.

## Technical Context

**Language/Version**: TypeScript (strict) on Node 24; Dart 3 with Flutter 3.47

**Primary Dependencies**:
- API: Fastify, Prisma (adapter-pg), @fastify/type-provider-typebox, @fastify/swagger(-ui), zod (env)
- Admin web: Next.js, React, Tailwind CSS, next-intl
- Mobile: flutter_riverpod, go_router, dio, flutter_localizations / gen-l10n

**Storage**: PostgreSQL, starting from an empty initial migration. No mobile local storage in
this feature.

**Testing**:
- API: Vitest; integration tests use `app.inject()` against a real test database
- Admin web: Vitest with React Testing Library
- Mobile: flutter_test (unit and widget tests)

**Target Platform**: Linux server for the API; desktop browsers for the admin web; Android 8+
and iOS 15+

**Project Type**: Monorepo with a web service, a web app and a mobile app

**Performance Goals**: Mobile first screen in under 2 s on a mid-range Android device. CI under
15 min.

**Constraints**: No secrets in the repo. The role picker exists only in debug builds. Russian is
the default language.

**Scale/Scope**: 2 endpoints, 7 admin placeholder pages, about 10 mobile placeholder screens

### Spec alignment notes

## Complexity Tracking

| Item | Why Needed | Simpler Alternative Rejected Because |
|------|------------|-------------------------------------|
| Debug-only role picker (Principle VII says the role comes from the authenticated session) | The role shells must be buildable and testable before the auth feature exists | Building auth now would multiply this feature's scope. The picker writes to the same `sessionProvider` that auth will use, so swapping it later touches one screen |
